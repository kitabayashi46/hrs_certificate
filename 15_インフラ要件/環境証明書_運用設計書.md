# 環境証明書システム 運用設計書

## 1. 目的

本書は、AWS ECS を利用した本システムにおける運用方針、監視、障害対応、バックアップ、リリース手順を定義し、安定したサービス提供を目的とする。

## 2. システム構成

### 2.1 構成概要

```text
利用者
  ↓
ALB
 ↓
ECS マネージドインスタンス/Fargate（1 Service / 1 Task）
 ↓
Aurora PostgreSQL
```

### 2.2 AWS利用サービス

|区分|サービス名|用途|
|---|---|---|
|コンテナ実行|ECS Fargate|アプリケーション実行|
|負荷分散|ALB|HTTPS受付|
|DB|Aurora PostgreSQL|データ保存|
|監視|CloudWatch|ログ・メトリクス監視|
|通知|SNS|障害通知|
|CI/CD|GitHub Actions|自動デプロイ|
|ネットワーク|NAT Gateway|外部API連携|
|ネットワーク|WAF|ファイアウォール|

## 4. 監視設計

### 4.1 ECS監視

|監視項目|閾値|通知|
|---|---|---|
|Task停止|1件以上|即時|
|CPU使用率|80%以上 5分継続|通知|
|Memory使用率|80%以上 5分継続|通知|

### 4.2 ALB監視

|監視項目|閾値|
|---|---|
|HTTP 5xx|5件/5分|
|UnHealthyHostCount|1以上|

### 4.3 DB監視

|監視項目|閾値|
|---|---|
|CPU使用率|80%以上|
|接続数|上限80%以上|
|空き容量|20%以下|

### 4.4 通知方法

- CloudWatch Alarm
- SNSメール通知

## 5. 障害対応設計

### 5.1 障害対応フロー

```text
アラート受信
↓
一次切り分け(500以外は金さん)
↓
CloudWatch Logs確認
↓
必要に応じ再起動 / 再デプロイ
↓
復旧確認
```

### 5.2 代表対応例

|事象|対応|
|---|---|
|ECS Task停止|Service自動再起動確認|
|アプリ500エラー|ログ確認 → 再デプロイ|
|DB接続不可|Aurora状態確認|
|高負荷|Task数増加検討|

## 7. リリース運用

### 7.1 デプロイ方式

- GitHub Actions による自動デプロイ
- main ブランチマージ時実行

### 7.2 手順

```text
ソース更新
↓
GitHub Push
↓
Docker Build
↓
ECR Push
↓
ECS Rolling Update
↓
正常確認
```

### 7.3 リリース判定

- ALBヘルスチェック正常
- 画面表示確認
- ログエラーなし

## 8. セキュリティ運用

|項目|内容|
|---|---|
|通信暗号化|HTTPS(ACM証明書)|
